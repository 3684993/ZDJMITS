## 根因及已核实事实

1. 相同Testnet凭据、相同旧域名：代理下account/openOrders/positionRisk全部TLS握手前断连；直连3/3成功。已设置binanceRestRoute=DIRECT、forceBinanceRest=false；保留WS、全局代理及TLS校验，未迁移交易所域名。新demo域名只验证了公共时间接口，不代表账户迁移验收。
2. income失败曾连带把账户判为UNAVAILABLE；并发REST同步没有全局单飞，旧响应可覆盖新状态；首页pipeline只在打开时读取，状态可长期过期。
3. 旧实例首先报database is locked，随后关闭数据库后的页面定时器继续读取，产生重复错误。已隔离会写主库的Temporal研究worker并修复关闭顺序；尚需在线证明不再复发。
4. 历史观察14仓/上限12；最新直连账户13仓，上限仍12。满容量不能凭20候选就继续加仓。没有扩大限额或强制平仓；旧设置审计缺乏前后值，无法完整还原超限形成历史。
5. 恢复快照约13MB改为约436KB核心+按实体增量更新，保留订单/成交/模型原文。旧9GB SQLite不会因删除少量行立即缩小；本轮未对主库VACUUM。
