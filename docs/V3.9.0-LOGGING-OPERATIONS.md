# V3.9.0 日志与验收操作说明

## 日志位置与保留

- 启动/致命错误辅助输出：data/runtime-logs/engine.stdout.log、engine.stderr.log。
- 运行日志：data/runtime-logs/engine-日期-实例ID-序号.jsonl。达到100MiB或跨UTC日期轮转，关闭文件gzip压缩；默认保留7天且总量不超过2GiB。
- 历史交易证据：SQLite中的runtime_events、订单执行账本、成交事实、ai_runs_archive；关键审计不适用运行日志的7天清理。
- 高频排名/选币/Shadow/池状态只输出30秒计数汇总。交易提交前审计仍同步落盘；运行日志采用异步有限队列，不能充当唯一交易账本。
- 本轮保留的旧stdout/stderr：data/runtime-logs/legacy-before-admission-20260909。主库旧遥测归档：data/telemetry-archive，逐文件附SHA256和行数清单。

## 正常运行时的检查入口（GET只读）

| 入口 | 重点 |
|---|---|
| /api/v3/diagnostics/private-sync | 最近成功/失败、连续失败、请求单飞、排队量与限流退避 |
| /api/v3/diagnostics/logging | 当前日志文件、queuedBytes、droppedOperational、writeFailures |
| /api/v3/diagnostics/storage | 待重试写入、overflow、checkpoint体积与耗时 |
| /api/v3/diagnostics/supply | 20常驻池、真实容量、候选原始拒绝原因 |
| /api/v3/diagnostics/p0-entry-integrity | 当前实例的订单/意图/方向/重复Primary完整性指标 |

日志字段包括timestamp、level、event、eventId、env、instanceId、buildId、traceId、symbol、durationMs、errorCode。runId→intentId→clientOrderId→exchangeOrderId→fillId通过持久审计链追溯；汇总日志不用于推断成交或未执行原因。

## 清理、故障和回滚

历史遥测使用 scripts/archive-runtime-telemetry.mjs：仅处理24小时之前指定遥测类型；先写gzip、回读校验哈希/行数，再选择精确删除原行。不要删除交易事实，不在运行主库上直接VACUUM或替换数据库。

日志队列丢弃、写失败、审计关联丢失必须明确报告。账户新鲜度不足限制新增风险；不能伪造READY，也不能用重启掩盖根因。关闭时先停止页面快照定时器，再关闭数据库。

Engine只能按AGENTS.md获得本次明确指令后手动启动，不能安装自动重启任务。生产写入锁仍有效；两小时隔离压力通过不代表24h/100真实生命周期或实盘准入已通过。
