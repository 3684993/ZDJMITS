# 2. 入场方向质量：日线 / 4h / 15m 是否真正决定方向

用户当前目标是让建仓方向主要依赖高周期到低周期的一致性，尤其关注：

- 日线趋势；
- 4 小时趋势；
- 15 分钟趋势与触发；
- 未来约 1 小时内的可达价格空间。

必须审计：

- 当前 Primary 输入中是否稳定、明确、结构化地包含日线、4h、15m 趋势事实？
- 这些周期的趋势方向由谁计算？程序、Scout、Primary，还是多个模块重复判断？
- 三个周期存在冲突时，当前系统如何决策？是否有明确、可追溯的证据链？
- LONG/SHORT 最终方向是否与 1D/4H/15m 的实际趋势一致？最近真实样本一致率是多少？
- 是否存在 15m 短时反弹覆盖 4h/日线主趋势，导致逆势入场？
- 是否存在日线/4h 已经反转但 AI 使用旧 packet/旧 K 线继续按旧方向入场？
- 9B 与 27B 对趋势方向是否经常不一致？最终采用谁的判断？
- Primary 完成时，入场所依据的高周期趋势事实是否仍然有效？
- 当前 122–175 秒甚至更长推理延迟，对 15m 触发的方向质量影响有多大？
- Entry 成交后 1m/5m/15m/1h 的 MAE（最大不利变动）是否显示“刚入场就逆向”是系统性现象？
- 按 LONG/SHORT、币种、市场 regime、趋势一致/不一致分组，入场后 5m/15m/30m/60m 的收益分布如何？
- “立即亏损”主要是方向判断错、入场时机差、maker 挂价位置差、信号已衰减，还是模型完成太慢？
- 当前是否有足够证据证明 AI 方向质量本身差，还是执行链把原本正确方向拖到错误时点？

必须要求实施计划把“方向判断质量”和“执行时效造成的方向失真”分开处理，不得混为一个问题。

# 3. 科学建仓数量：谁是真正的 sizing authority

当前最核心的问题之一是：**AI 分析完成后，为什么最终经常形成极小仓位，且仓位规模与可用资金、机会质量、预期净收益不匹配。**

必须完整追踪当前 build 至少 20 个自然 Entry 样本：

`Candidate → Scout → Primary raw output → normalized decision → TradePlan → planned notional/margin → reservation → intent → JIT → adapter qty → exchange order`

逐层回答：

- 当前真正决定 qty / notional / margin / leverage / position size 的唯一权威是谁？
- AI 是否能明确决定仓位大小？如果可以，字段是什么，后续是否被覆盖？
- 如果 AI 不能决定，机械 sizing 使用了哪些输入？
- 是否存在多个 sizing authority，最终采取 min() 或反复裁剪？
- 约 5 USDT、几十 USDT 的小单第一次出现在哪一层？
- 是否存在 test size / canary / probe / default / fallback / fixed margin / candidate budget / lease budget 等隐式小额值？
- 系统设置中的最低建仓金额（如 100 / 200）到底定义为什么：保证金、notional、目标仓位价值还是别的？
- 该值是否真的进入最终执行契约？
- 当前 `Qty × Price`、保证金、杠杆后名义金额之间是否存在单位混淆？
- leverage 是否被重复乘、重复除，或在 AI/TradePlan/adapter 多次换算？
- quantity rounding、step size、maker reprice 后是否可能让最终交易金额跌破系统最低值？
- 交易所最低成交金额与系统最低建仓保证金/交易金额之间是否被混淆？
- 资金充足时，为什么仍会形成经济上无意义的小单？
- 当可用资金约 4,000+ USDT/USDC 时，单笔资金使用比例的实际分布是多少？
- 高置信度与低置信度机会当前是否得到几乎相同的仓位大小？
- 当前 position slot / lifecycle / TP / AI review / reconciliation 成本，对 5 USDT 小仓和 200+ USDT 仓是否近似相同，从而造成明显资源浪费？

必须明确：**微小单到底是模型决策、配置定义、金额单位错误、旧测试逻辑、资本分配算法，还是后置执行链缩放造成。**

# 4. 最低建仓保证金 / 最低交易金额必须被重新定义和验真

用户希望最终系统能够明确处理以下三个概念，但本轮不要预设它们一定相同：

- 系统最低建仓保证金金额（例如 100 / 200）；
- 系统最低交易 notional；
- 交易所强制最小成交 notional / minQty。

必须回答：

- 当前三者是否有独立定义？
- 当前 UI、Settings、模型 prompt、TradePlan 和 ExchangeAdapter 是否使用同一含义？
- 是否存在“UI 显示 200，但执行只要求交易所最低 5 USDT 左右”的情况？
- 是否存在“200 是保证金，但代码却当 notional”或相反？
- 杠杆倍数改变后，最低保证金与最低 notional 应如何关联，当前代码实际如何处理？
- 最终 order submit 前是否重新验证真实最终数量对应的保证金/notional？
- reprice/rounding 后是否可能跌破系统业务最低值？
- 当前 build 所有小单中，有多少低于系统设置的业务最低值，有多少只是高于交易所最低值？
- 不同 quote asset（USDT/USDC）是否存在不同路径或单位错误？

实施计划必须基于当前真实字段和真实单位重新说明权威来源，不能继续沿用含义不清的“最低金额”。

# 5. 最低净收益目标：当前系统有没有真正的经济性闭环

用户希望系统能够围绕“最低净收益”形成可解释的建仓数量与止盈目标，例如当前可能配置为 2 USDT，但具体值必须先从 Settings 验真。

必须审计：

- 当前是否存在唯一的 minimum net profit / target net profit 设置？
- 该值作用于 Entry、TP、AI Exit 还是仅 UI/告警？
- 当前系统是否先决定仓位，再被动检查目标收益，还是根本没有闭环？
- 对一个给定交易对，当前是否能从数量、价格、杠杆、手续费、预期滑点、资金费、TP 距离推导预期净收益？
- 当前 TP 目标是否可能在手续费后低于最低净收益？
- 当前小单是否即使 TP 成交也只能产生几毛钱甚至更低净收益？
- `TP_LOW_NET_TARGET_KEPT` 和 `economicWarning` 当前是真正的异常信号，还是只是记录后继续交易？
- 最近真实 Entry/Exit 周期的毛收益、双边手续费、资金费、净收益分布是多少？
- 最低净收益目标与持仓时间、波动率、交易对价格、杠杆之间当前有没有任何动态关系？
- 当前是否存在“收益目标固定，但仓位金额极小，因此 TP 必须极远”或“TP 很近，但净收益没有经济意义”的两类失败？
- 是否存在高单价币种和低单价币种使用相同静态规则导致结果失真？

必须要求实施计划回答：**当前系统有没有一个从机会质量 → 仓位规模 → TP → 费用后净收益的闭环，还是这些环节彼此独立。**

# 6. 未来 1 小时可达收益：当前 AI 是否真正做过这种推理

用户希望建仓决策更关注未来约 1 小时内是否存在足够可达收益，而不是无限期持仓等待。

必须审计：

- 当前 Primary 是否显式预测未来约 1h 的价格路径、波动区间或可达目标？
- 如果有，是自然语言判断还是结构化数值？
- 如果没有，当前所谓 target/horizon 的实际含义是什么？
- 当前 horizon 是否与 15m/4h/1D 趋势混在一起？
- 过去自然交易中，AI 目标价格在 1h 内实际触达率是多少？
- 目标未触达时，是方向错、幅度过大、入场太晚还是波动不足？
- 对不同 ATR/波动水平、不同币价和不同时间段，可达空间是否有明显差异？
- 当前系统是否对“1h 内可达的毛收益空间”与“双边费用后的最低净收益”做过同一口径比较？
- AI 是否可能为了达到固定净收益目标而选择市场在 1h 内几乎不可能触达的 TP？
- 是否存在低波动币种占用仓位数小时甚至数天，但潜在收益非常低？

这里的核心不是承诺 1 小时一定盈利，而是验证当前系统是否具有**时间约束下的收益可达性判断**。

# 7. 止盈价格：为什么低收益、为什么持仓久

必须把止盈问题与仓位大小一起审计，而不是孤立调 TP。

重点回答：

- 当前 TP 的主要权威来源实际是哪一类：AI / STRUCTURE / FIXED / HUMAN / fallback？
- 当前新仓 TP 距入场价的百分比分布是多少？
- 按实际 notional 计算，TP 成交时的预期毛利润/净利润是多少？
- 微小仓位是否导致“收益过低”或“为了达到最低收益被迫把 TP 放太远”？
- 当前 TP 是否与 15m/1h 波动空间匹配？
- 当前目标是否与 4h/日线趋势方向一致？
- 当前存在多少仓位 1h 内从未接近 TP，却持续占用仓位？
- 当前持仓年龄与 TP 距离是否高度相关？
- 长持仓是 TP 不合理、方向错误、市场 regime 改变、退出权威关闭，还是多因素叠加？
- 真实 TP 成交的净收益和持有时长是否体现出经济效率？

要求实施计划明确区分“TP 价格问题”和“仓位规模问题”，并证明哪一个是主要根因。

- 当前低平仓率中，有多少是因为 TP 没触达？
- 有多少是入场方向错误导致长期浮亏？

- 人工接管后是否只是“停止 AI”，却没有形成任何收益/时间管理闭环？
- 当前是否存在“新仓不断产生、旧仓长期不退出”的资本和分析资源堆积？

最终必须给出平仓率低的根因占比/证据等级，不能一句“AI Exit 关闭”结束。

实施计划必须基于实测价值决定模型职责，而不是因为历史架构已经存在就默认保留所有步骤。

# 12. 新实施计划必须围绕的业务目标

新的计划必须由你自行设计，但必须明确回答如何验证以下目标是否被实现：

1. **不再出现经济上无意义的微小 Entry**；
2. 系统业务最低建仓保证金/交易金额有唯一权威定义并在最终订单上真实成立；
3. 仓位规模与可用资金、机会质量、交易对价格、杠杆、最低净收益、手续费和可达波动空间之间存在清晰可追溯关系；
4. 1D / 4H / 15m 趋势事实在方向决策中有明确作用；
5. 明显减少入场后短时间立即逆向的交易；
6. TP 在经济上有意义，并与仓位规模和约 1h 可达空间匹配；
7. 长时间低收益占用仓位的情况明显减少；
8. 风险/组合监测不再成为 AI sizing 和 Entry 的主要干预源；
