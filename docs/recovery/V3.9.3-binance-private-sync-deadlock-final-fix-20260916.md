# V3.9.3 Binance 私有同步死锁最终修复

日期：2026-09-16
分支：`v393-private-truth-tp-canary-20260916`
PR：#8

## 实证故障

本地仍出现：

`BINANCE_REQUEST_BUDGET_DEFERRED:SATURATED ... endpoint=/fapi/v1/time ... source=CLOCK`

由此导致 signed private 调用无法取得时间戳，`/account`、仓位、订单、TradeRecord reconciliation、人工操作及自动 Entry 连锁失效。

## 根因

1. `BinanceTransport.json()` 在 `RequestBudget` 之前存在 SATURATED 预拦截；上一轮只修内部 budget queue，因此 CLOCK/PRIVATE_STATE 仍在进入保留通道前被拒绝。
2. REQUEST_WEIGHT 阈值固定 1000/1800/2200，未使用 Binance `exchangeInfo.rateLimits` 当前 `REQUEST_WEIGHT/MINUTE`。
3. Entry gate 把 `PRESSURED` 也当阻断，并可能被旧 proxy route 的历史 SATURATED 状态污染。
4. `/income` 权重高但属于收益/审计补充，不应与账户、仓位、订单真相竞争保留容量。
5. 第一次 private sync 发生在市场 bootstrap 之前，因此需要在第一次 signed CLOCK 前主动发现交易所当前 request-weight limit。

## 最终实现

- 四车道：`EXECUTION` / `CONTROL` / `PRIVATE_TRUTH` / `PUBLIC+BACKGROUND`。
- Transport 只提前丢弃 PUBLIC/BACKGROUND；不再因本地 SATURATED 直接拒绝 CLOCK、RATE_LIMIT_CONTROL、PRIVATE_STATE、ORDER_VERIFICATION、RECONCILIATION、EXECUTION。
- 首次 signed CLOCK 前 single-flight 请求 `/fapi/v1/exchangeInfo`，读取 `REQUEST_WEIGHT/MINUTE`；失败时仍由受控 CLOCK probe 恢复，不形成递归死锁。
- 动态预算：public 50%，background 72%，new-entry hard gate 85%，private truth reserve 95%。
- Binance 真正返回 418/429 后 `blockedUntil` 继续严格 fail-closed。
- `/income` 改为 `BACKGROUND_AUDIT`，先于 private truth 被 shed。
- `PRESSURED` 不阻止 Entry；`PRIVATE_ONLY/SATURATED/RATE_LIMITED/RECOVERING/PERSISTENCE_FAILED` 才阻止新增风险。
- Entry gate 支持当前 route，并在无 route 参数时只采用最近活跃 route，避免旧代理状态污染。
- POST `/order` 的 0 REQUEST_WEIGHT 写入不会仅因本地 REQUEST_WEIGHT SATURATED 被拒绝；Testnet/proxy 写锁不变。
- UNKNOWN 重型证明仍限频，`/income` 不参与 UNKNOWN 风险证明。
- 人工操作仍保留账户 READY 的 fail-closed 要求；修复目标是让真实 `/account` 获得保留通道并正常恢复 READY，而不是绕过账户真相。
- TradeRecord 使用已有 `PositionService.ensureOpenRecord()` 回填 `positionId`，不建立第二套生命周期。

## 本地验收硬条件

- `npm run verify` PASS。
- 启动后 request budget 显示 `limitSource=BINANCE_EXCHANGE_INFO`。
- 不再持续出现 `/fapi/v1/time -> BINANCE_REQUEST_BUDGET_DEFERRED:SATURATED`。
- private sync `lastSuccessAt` 持续前进，account=READY。
- 持仓刷新、人工控制恢复；TradeRecord 的 positionId 随 reconciliation 回填。
- 当前 route 无新增 418/429；PUBLIC/BACKGROUND 在压力下先被 shed。
- 账户新鲜且预算低于 hard gate 后 Entry/AI/Submitted/Filled 恢复。

禁止为了通过验收清 DB、删除现有 Binance 订单/仓位或绕过 UNKNOWN/fail-closed 保护。
