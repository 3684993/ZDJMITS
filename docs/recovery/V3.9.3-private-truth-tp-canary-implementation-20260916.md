## Scope

This is a small V3.9.3 recovery/canary patch based on the 10-hour Testnet evidence ending 2026-09-16 07:16 +08. It does not change entry direction authority, leverage, sizing, model routing, DB schema, or the overall architecture.

## Implemented

1. Binance request budget now treats fresh `x-mbx-used-weight-1m` as admission truth even after counter-domain discontinuity. This addresses the observed case where the proxy exit reached 6106 while the process-local estimator was materially lower.
2. `/fapi/v1/exchangeInfo` is single-flight, preventing concurrent symbol hydration from generating duplicate refreshes.
3. Signed private requests reuse server-time offset for 30 seconds instead of 5 seconds while preserving single-flight clock refresh.
4. UNKNOWN active-risk proof uses a lean `userTrades + allOrders` path; `/income` is no longer requested for this proof.
5. UNKNOWN-driven exchange-wide reconciliation scans are bounded to once per 60 seconds. Exact order checks remain fail-closed, and valid 5-minute no-active-risk evidence remains effective between scans instead of repeatedly consuming risk capacity.
6. No second TradeRecord attribution architecture was added. Existing `PositionService.ensureOpenRecord()` remains the canonical cycle-based backpatch path and must be validated after private reconciliation is healthy.
7. Full-position TP canary enforces a minimum 1.20% move from entry for newly selected/repaired 100% TP targets. AI full-position TP requires an explicit `15m` evidence reference plus a fresh closed 15m card. 1m/5m evidence cannot independently pull a full-position target inside the canary floor.
8. Fixed TP default is changed from 0.45% to 1.20%. The Guardian also enforces the 1.20% floor for a full-position target, so a persisted legacy 0.45 setting cannot bypass the canary when a new/repaired TP is selected.
9. Existing legal WORKING TP orders are not blindly canceled/repriced at startup. Exchange truth is reconciled first.
10. A local WORKING TP no longer receives a fabricated fresh `tpLastVerifiedAt`. If executable bid/ask has crossed the TP while the position remains open, Guardian performs exact Binance TP verification, switches coverage to PENDING, and caps this exact check to once per 30 seconds per order.
