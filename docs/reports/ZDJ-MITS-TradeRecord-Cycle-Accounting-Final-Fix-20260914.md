## 1. 47 orphan Exit fills 根因
旧 PositionService.recordExchangeFill 写入 executionFills 并更新活动 lifecycle，但只有 ENTRY 分支更新 TradeRecord。Exit 到达时没有完成 TP order → 原 cycle → TradeRecord 写入；RECONCILIATION 关闭后到达的 Fill 也不补记。活动 lifecycle 只按 symbol/side 保存最新周期，不能作为历史归属证据。
47 条中：10 条能够由同一 exchange order 的已链接 Fill 锚点定位记录；37 条虽有 TP 订单，订单只指向复用的 exchange positionId，缺少永久 cycle 绑定。最后这 37 条保持 UNKNOWN。附表逐条列出 tradeId/orderId/去向。

## 2. 17 missing-fact cycles 根因
仓位从交易所当前列表消失时 finalizeSafe 立即写 CLOSED/closedAt；该时点未必已收到全部 Exit。Exit 用户数据未驱动原记录重算，且 EntryOrder lookup 无法证明 TP ownership，因此留下 EXIT_FACT/FEE_FACT/EXCHANGE_FILL_CONSERVATION。缺失手续费是缺完整成交事实的结果，不能补零。

## 3. 10 quantity-conservation failures 根因
observeRemotePosition 的 REDUCE 分支把 entryQty 改为 remote.quantity（剩余仓量）；Entry re-attribution 也用当前持仓量覆盖历史 entryQty。旧 record/lifecycle 重用又把不同周期 Fill 混到同一记录。finalizeSafe 只检验 exitQty >= entryQty，而完整性服务要求严格相等，导致伪 COMPLETE 随后降级。

## 4. OPEN + closedAt 根因
ensureOpenRecord 允许 existing.status=CLOSED 但 cycleId 相同的记录返回；Entry/reconciliation 又 spread 旧记录并设置 status=OPEN，未清除旧 closedAt。repairOpenEntry 同样曾保留 closedAt。现在新周期建立新 record，CLOSED 不复活；观察到归零但缺 Exit 时记录 observedClosedAt，状态 INCOMPLETE，而非伪 CLOSED。

## 5. 修复后的 cycle identity
EntryOrder 提交前使用基于永久内部订单 ID 的 cycleId；该字段进入持久 EntryOrder、ExecutionFill、Position、TP/Manual Order 和 TradeRecord。未有真实 Entry 证据的导入仓位建立独立未知周期，不能通过 symbol/数量/时间猜认旧 Entry。真实 Entry fill 可在仓位快照前建立记录。活动生命周期关闭后再次开仓使用新 cycle；closedAt 不作为关联键。
cycleAccounting.accountCycle 是纯计算入口：entryQty/exitQty 按 symbol+exchange tradeId 去重累加，remainingQty=entryQty-exitQty，容差 max(1e-10, entryQty×1e-8)。负差额保持冲突；部分退出为 PARTIALLY_CLOSED/closedAt=null。所有退出事实守恒才最终 CLOSED。

## 6. Exit exact attribution
优先查已持久 tradeId/Fill，再以 symbol-scoped exchange orderId、clientOrderId 找 Entry/TP/Manual Order 和已有同订单 Fill 锚点；通过订单 cycleId 或唯一持久 positionId→record 绑定回到 cycleId→TradeRecord。多个精确候选冲突则拒绝归属。Binance BOTH 根据原周期方向识别 Entry/Exit。不会只查 EntryOrder，更不会按 symbol+时间连接。
跨日 Sync 从本地持久周期加载昨日 Entry 与全部已保留 Fill；窗口仅决定本次新审计事实。无精确周期证据继续 UNCLOSABLE，不生成猜测周期。Preview 纯读；Apply 仍需明确确认。移除了旧按 symbol/时间重建的 repairClosedCyclesFromAudit 入口。

## 7. Fee / funding accounting
分别保留 entryFee、exitFee、grossRealizedPnl、tradingNetPnlExFunding、fundingAttributionStatus、netPnl。显式 commissionUsd=null 不再通过 ?? 变成零。真实零佣金仍允许零。非稳定币未获兑换事实时保留未知。
COMPLETE 定义为成交/手续费/数量守恒完整，不要求 funding 精确；这是交易账本完整性，不能代替完整 canonical 净收益。funding 未精确归属时：funding=null、fundingAttributionStatus=UNKNOWN、pnlBasis=CANONICAL_NET_WITH_FUNDING_UNKNOWN、netPnl=null。TRADING_NET_EX_FUNDING 由独立 tradingNetPnlExFunding 字段表达。
只有 fundingAttributionStatus=EXACT 且 funding 有真实值时，canonical netPnl=tradingNetPnlExFunding+funding（funding 为带符号现金流）。正式收益/Experience 查询排除未知 funding；本次没有假设 funding=0。
