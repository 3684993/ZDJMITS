## P2 — zero Entry capacity

**Finding / classification:** `POLICY-BINDING`, **NOT A BUG**. At 02:52:43.947 UTC, the canonical Entry occupancy set had 22 positions, all `HUMAN_MANAGED`, with position gross `$11,196.33857498`; there were zero Entry orders occupying risk and zero active unexpired Entry reservations. Thus the single-book calculation is `gross = positions + included pending = $11,196.33857498 + $0`, against the approved `$10,811.957` cap. `headroom=max(0,limit-used)=$0`; `shortfall=max(0,used-limit)=$384.38157498`.

The limit is from Settings version 219 in the same database snapshot. Current directional totals are LONG `$3,655.74320558` and SHORT `$7,540.59536940`, each below `$8,649.565`; neither direction is the present first aggregate constraint. Correlation mapping is empty and the cluster cap equals gross. Human notional cap also equals gross. The source removes those equal/wider duplicate vetoes, but that simplification cannot make an above-limit aggregate eligible.

Pending-order dedupe is implemented in `collectPendingEntryRiskExposures()` (`entryRiskOccupancy.ts:199-226`): a qualifying order replaces its linked reservation; reservations without a qualifying order are counted once; unreserved qualifying orders are retained. At capture, reservations were zero and all 47 Entry UNKNOWN rows had current identity-bound absence proof, so included pending notional was zero. No Entry gross was omitted from the prescribed source set or counted twice in this replay. Historical Phase 0's ~$402.49 shortfall differs because the position marks moved; it does not contradict this later snapshot.

The code does not forcibly close existing positions when the book exceeds its approved cap. `PortfolioRiskAdmission.computeCapacityFacts()` sets gross room to `max(0, maxGross - snapshot.gross)` and intersects that with side, cluster, margin, and stress capacities (`portfolioRiskLedger.ts:491-543`). Therefore a new order cannot fit until ordinary position/exit activity naturally takes canonical gross below the approved limit. No limit increase, threshold widening, order manufacture, or forced close is proposed.

**Risks:** treating released Entry claims as absent exposure without applying the current order proof predicate would understate risk; treating them as permanently active despite renewed identity proof would overstate it. The read-only replay used the source's exact proof fields and predicate. We did not run a fresh in-process admission evaluation; current source/build identity remains an acceptance item for a later authorized runtime validation.

## P3 — next likely blockers after natural gross headroom returns

**Finding / classification:** no current post-gross conversion failure was reproduced from a complete current candidate/market snapshot (`NOT_REPRODUCED` for live frequency/rate). The source has independent risk, execution correctness, and economics conditions listed in `P3-BOUNDARIES.json`. Their order is an audit ordering, not a claim about a future candidate's first blocker.

The measurable boundaries are:

1. **Independent portfolio risk:** for the current book, `grossRoom=max(0,Glimit-G)`. Per side the book ceiling is the minimum of direction room, candidate-specific cluster room, stress-loss bisection room, capital-at-risk/margin room converted by verified leverage, quote-asset margin room converted by verified leverage, and gross room. `stressCapacityUsd()` runs 64 bisection steps against the configured loss-valued scenario evaluator (`portfolioRiskLedger.ts:468-488,520-533`). Directional room now is `$4,993.82179442` LONG and `$1,108.96963060` SHORT, but gross room is zero. Exact post-gross stress/margin room is **unobserved** in this persisted-row replay; no inferred values are substituted.
2. **Cluster:** current map `{}` sends exposures to `UNMAPPED_CORRELATED`; with cluster cap `$10,811.957 >= gross cap`, source suppresses cluster as an independent stress veto. A future mapped underlying bucket is independent only when its own aggregate ceiling is tighter than gross or it is otherwise the binding configured loss/risk fact.
3. **Exchange quantity interval:** for step `s`, entry price `p`, min quantity `qmin`, and min notional `Nmin`, smallest legal step-units are `uMin=max(1, ceil(qmin/s), ceil(Nmin/(s*p)))`; envelope maximum is `uMax=floor(min(maxQuantity, maxNotional/(s*p), maxMargin*leverage/(s*p)))`. A legal size exists iff `uMax>=uMin` and tick/step/price/leverage facts are proven. `quantityLadder()` starts at the legal minimum, so it does not start below minNotional (`quantityHorizonCandidates.ts:42-50`).
4. **Economics/target:** the minimum legal size must clear `expectedNetProfit >= max(minNetProfitUsd, ROI-derived floor)` at a tick-aligned target. Current `minNetProfitUsd=$1`, `minNetProfitRoiPct=0.15`; this arithmetic floor binds in SHADOW too. Statistical reachability/history only vetoes when `tradeEconomics.admissionMode==='ENFORCE'`; current mode is SHADOW. The implementation intentionally does not increase quantity merely to clear the absolute profit floor (`quantityHorizonCandidates.ts:65-88,140-180`).
5. **Horizon and market facts:** legal horizons are selected from configured integer horizons between 5 and 1,440 minutes; no allowed horizon means `NO_LEGAL_TARGET_HORIZON`. Quote freshness, private account/execution readiness, and JIT validity remain independent execution facts; no fresh candidate data were captured here, so incidence is unobserved.
6. **Reservation/idempotency/UNKNOWN:** a candidate must survive fresh admission and durable claim/reservation identity. Active Entry UNKNOWN contributes remaining notional `max(0,quantity-filledQuantity)*price`, with order replacing its reservation; it is released only under current matching no-risk proof. This is execution/risk correctness, not diagnostic-only.
7. **Frozen model quantity:** the model-proposed triple is validated against the generated candidate set. An unoffered choice is rejected by `tradePlanService.ts:92-117`; it is not silently changed to a smaller quantity or different side. The set may still contain smaller executable candidates, but this AI choice can produce no plan. This is **not a proved hard-capacity false zero**: it is a deliberate immutable-choice rule. A future human-approved optimization could present the allowed quantity/horizon/target candidates before model selection; do not auto-clamp or resize the authorized quantity as a hidden behavior.

Accordingly, no evidence supports changing the quantity floor, risk thresholds, or fail-closed facts. A future implementation should first add a deterministic synthetic test for the legal interval and model-choice mismatch, then use read-only candidate replays to measure the observed blocker distribution. Do not use old 72-hour failures as current proof.

## P4 — minimum authoritative risk readback

**Finding / classification:** `OBSERVABILITY-GAP`. Phase 0's running build published a refusal and zero ceiling while its `riskAdmissionGates` and `riskAdmissionReasons` arrays were empty. Current source holds numeric `gates`, first binding, snapshot hash, risk generation, and profile version inside `PortfolioRiskAdmission` (`portfolioRiskLedger.ts:491-543,556-607`), but the book adapter deliberately projects a smaller `AdmissionCapacityView` and `AdmissionBookSummary` (`admissionCapacityReader.ts:9-18,63-64`). A book-level pre-model refusal can therefore be summarized without its numeric gate array; `pipelineVerdict.ts:70-80,134-139` has a fallback using that summary and emits empty `gates`/`reasons` when no candidate-level denial was recorded.

Recommended single-readback shape: `evaluatedAt`; `scope=BOOK|CANDIDATE`; candidate symbol/side/quote asset/verified leverage when relevant; settings/profile version and authority content versions; risk generation + snapshot hash; coverage and owner/account/private-fact freshness; every gate `{name,unit,used,limit,headroom,shortfall,candidateImpact,clusterKey}`; first binding; per-side ceilings; `AVAILABLE|UNAVAILABLE|ZERO`; and included Entry pending/reservation lineages with source/status/proof-valid flag and dedupe identity. Keep the existing single admission as the only authority. Carry its facts through book adapter, verdict, snapshot/API, and dashboard without recomputing or reranking another gate. UNKNOWN details should be bounded/redacted, with stable hashes/identities rather than full credentials or user payloads.

**Risks:** adding a second ledger, letting a dashboard calculate capacity, or treating a missing readback as an available zero would reintroduce contradictory authority. Additive JSON fields should remain backward-compatible; no persistent schema migration is indicated by the inspected paths.
